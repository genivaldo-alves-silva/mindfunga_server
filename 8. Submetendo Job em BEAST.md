# 8. Submetendo Job em BEAST

- Para cadastro, primeiro acesso e envio dos dados de input ao servidor, veja os itens [1](/1.%20Cadastro,%20Configuração%20e%20Primeiro%20acesso.md) e [2](/2.%20Criando%20e%20submetendo%20o%20Primeiro%20Job%20(Mrbayes).md).

## 8.1 Tipo de arquivo e análise

- A submissão será relativamente simples ao usar algo como 'beast input.xml' no teu terminal. No entanto, a submissão deve ser feita usando o gerenciador de jobs.
- Você deve gerar o .xml no teu computador usando o executável java Beauti.
- Obtenha o Beauti no site [beast2.org](https://www.beast2.org/).

- Para primeira análise, caso não tenha o teu arquivo .xml gerado pelo Beauti, use o arquivo de exemplo - [input.xml](/BEAST_Jobs/input.xml).

## 8.2 Submentendo BEAST job

- Edite o arquivo mrbayes.sub, cole o conteúdo abaixo (ie.: Ctrl+Shift+V ou Ctrl+V).


```bash
# para editar digite
nano beast.sub
```

- Veja o arquivo de submissão de exemplo - [beast.sub](./BEAST_Jobs/beast.sub).
- Veja o arquivo de input de exemplo - [microtest.xml](./BEAST_Jobs/microtest.xml)

```ini
# O executável do BEAST que vinculamos em /usr/local/bin/
executable              = /usr/local/bin/beast

# Argumentos: -threads define o uso de CPUs, seu_arquivo.xml é o input
# em log, output e erro, você pode definir os nomes dos arquivos de log
arguments               = -beagle -beagle_SSE -threads 4 -overwrite microtest.xml

log                     = beast.log
output                  = beast.out
error                   = beast.err

#should_transfer_files   = YES
#when_to_transfer_output = ON_EXIT

# Recursos solicitados (devem ser compatíveis com o -threads acima)
request_cpus            = 4
request_memory          = 6G
request_disk            = 7G

queue
```
Após colar o conteúdo, salve usando "Ctrl+X" em seguida "y" ou "s" e por fim "Enter".

- De volta ao terminal:

```bash
condor_submit beast.sub

# Anote o número do job como do exemplo abaixo: job nº 16
# | Submitting job(s).
# | 1 job(s) submitted to cluster 16.

# verifique se o teu job foi submetido e se está rodando (em RUN)
condor_q

# Caso não apareça nada ou o job fique com HELD e não HOLD, verifique o arquivo de erro
# use cat para ver o conteúdo do arquivo sem abrir um leitor
cat beast.err

# ou
# use nano para ler em uma janela específica com direito à edição
nano beast.err

# se estiver em IDLE pode ser que não tem recursos disponíveis e quando houver o condor se engarregará de colocar para rodar
# se estiver em HOLD, a submissão de job pede algo que não existe no servidor
# para mais detalhes você pode verificar o arquivo .err

# Quando running, use o comando abaixo para acompanhar o andamento da análise
tail -f mrbayes.out

# Para sair digite Ctrl+C
```

## 8.3 Arquivos de saída

- .trees - faça o download e use o treeannotator no teu computador para fazer burn-in e árvore consenso;
- .log - faça download e use o logcombiner no teu computador.
